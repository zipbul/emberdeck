# 카드 작성 공통 규율

모든 쓰기는 `ed` CLI로만 한다(파일 편집 도구 없음).

## 절차
1. `ed card schema <type>`로 필드·스켈레톤을 받는다.
2. `ed card list --type <type>` — 기존 카드가 있으면 그 **실제 키**로 수정, 없으면 생성.
3. 생성 `ed card create <키> --type <type> --summary "<요약>" --from -`; 수정은 namespace **전체**를 `ed card update <키> --patch -`로 재제출(부분 아님).
4. `ed card get <키>`로 본문이 실제로 저장됐는지 확인한다 — **본문 없는 draft도 `validate`는 0을 낸다(false-green)**. 저장 확인 전에는 성공을 보고하지 않는다.
5. `ed validate cards`가 0으로 끝나는지 확인한다. (스키마·enum·참조만 봄 — 의미적 소유는 안 봄.)
6. **세트 소유 대조 (한 세트로 2개 이상 카드를 저작·수정했을 때).** 각 카드를 다시 판단하지 말고, 모든 카드 scope의 IN에 적힌 **책임을 한자리에 모아 나란히 놓고 충돌만 조회**한다: ① 같은 책임이 둘 이상 카드 IN에 있으면 = 중복 소유 위반. ② 한 카드가 다른 카드 IN의 소유물을 자기 scope에서 참조·전제하면서 그 대상에 `cross_domain_dependency`(또는 상응 참조)가 없으면 = 미선언 소비 위반. 잡히면 소유자 쪽에 남기고 침범 clause를 제거하거나 의존을 선언해 고친다. (재판단은 원저자 확증편향으로 같은 오독을 재승인하므로 금지 — 나란히 놓은 충돌 조회여야 한다.)

## 근거
개념 tier(vision·principle·domain·brief)는 **의도 문서**(CLAUDE.md·README·전략 문서)에서 도출하고 코드로 정당화하지 않는다(spec만 코드 기반). 소스 문장으로 역추적 안 되는 주장은 **필드에 넣지 말고** `근거 없음`으로 보고한다 — "partly inferred" 같은 뭉갬 금지.

**이름은 저작하지 말고 인용하라.** 현재 카드 바깥의 무언가를 식별하는 이름은 전부 참조다 — 그것이 속한 이름공간(코드의 @spec 접두, 덱의 실제 카드 키)에서 **문자 그대로 인용**하고, 시스템이 해소를 검증하는 필드에 쓴다. 해소되는 자리가 없으면(예: scope 산문) 이름 대신 책임으로 서술하거나 실제 키를 정확히 인용한다 — 동의어를 새로 짓지 마라.

## 출력
사용한 문서 · 쓴 값(수정이면 diff) · 사용자 판단이 필요한 `근거 없음` 공백.
