# domain 카드 판단

## domain이란
의도에서 나온 하나의 관점 아래 묶이는 **의미 단위**다. 전체가 아니라 부분이다.

## 후보 검사 (필수)
각 domain 후보마다 **그것이 의도 문서의 어떤 문장에서 나온 관점인지** 대라. 못 대면 domain이 아니다 — 코드·디렉토리·기존 카드가 아니라 의도가 근거다.

## 구별 기준
두 영역이 (1) 각자의 용어·규칙을 갖고 (2) 서로 다른 이유로 바뀌면 별개 domain이다. 애매하면 이 둘로 판단하고 결정한다.

## 작성 규칙
- **overview** — 이 의미 단위가 무엇이고 왜 존재하는지.
- **scope** — 무엇이 IN이고 무엇이 OUT인지 명시. 다른 카드 바깥을 식별하는 이름은 저작하지 말고 실제 키를 문자 그대로 인용한다(card-agent 규율).
- **의존** — cross_domain_dependencies는 **의존하는 쪽(depender)이 소유**한다: A가 B를 필요로 할 때만 A 카드에 A→B를 적고, B 카드엔 적지 않는다.
